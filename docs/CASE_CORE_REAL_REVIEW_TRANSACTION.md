# C.A.S.E. Gate D — review transaction implementation (dormant)

The neutral queue and immutable history read routes are deployed, but real case review writes were previously available only through the explicitly fixture-gated repository path. This candidate factors their common core into a single exact-installation transaction. The existing `ApplySynthetic` still requires the fixture/caller capability flags; a separate `ApplyReviewed` is an internal repository method intended for a future authenticated staff route.

Within the transaction it re-reads same-organization OWNER/ADMIN membership, joins the selected installation, Discord guild connection and game server, locks membership through commit, locks exactly the scoped case row, checks a strict transition and neutral reason, rejects malformed/mention-containing notes, and appends immutable audit plus status change atomically. Idempotent replays require identical action identity and renewed current membership. A role revocation and concurrent review serialize. The new method **cannot create findings, case records, outbox entries, Discord messages or sanctions**.

There is intentionally **no HTTP/runtime caller, toggle or route** in this PR. A future route must derive actor and installation from `requireCapability` and the selected installation rather than accepting those IDs from JSON, rate-limit the write, and be default-off until an independently validated detector and admissible source create an actual case. An OWNER/ADMIN membership role check in the repository is necessary but does not replace the application's admin capability check. UI/review acceptance will follow implementation.

Disposable-schema integration tests exercise both fixture and non-fixture entrypoints, outsider and foreign-installation refusals, exact replay and atomic state/history. The current case admission remains blocked with CASE-MOV-001 and source gate A is still open pending corrected health readback. No live alerts or enforcement activated.
