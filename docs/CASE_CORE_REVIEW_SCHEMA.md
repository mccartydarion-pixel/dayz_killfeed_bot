# C.A.S.E. core: inert review/outbox schema candidate

This draft adds migration `0063_case_review_outbox_skeleton` **only after a separate production authorization**. The repository currently has applied `0056_case_shadow_evaluations`; an older unmerged billing candidate reserved names 0057–0062. Before any later billing merge, reconcile the registration/order with existing production migration history. Never rename an already applied migration.

Tables: `case_review_cases`, `case_review_evidence`, `case_review_audit`, and `case_staff_outbox`. Composite foreign keys bind a case's guild, game server, Discord guild connection, and installation, then bind exact evidence and outbox rows to the same scope. Unique evidence fingerprints and action/delivery keys prevent fixture duplicates. The review audit rejects direct UPDATE/DELETE through a database trigger, while case-linked evidence, audit, and delivery foreign keys use RESTRICT to prevent deleting a case to erase its history. Privileged database owners can still change schemas, so application-role separation and operational retention policy remain necessary. Check constraints reject impossible outbox status/lease/receipt shapes. The outbox stores no Discord destination or arbitrary message payload; any future worker must freshly resolve the private CASE_ALERTS destination, check permissions and owner opt-in, and independently authenticate reviewers.

**Explicit omissions:** no production writer/reader, HTTP endpoint, migration trigger that emits alerts, scheduled work, live finding admission, notification sender or enforcement. Database constraints alone do not prove semantic detector eligibility, append-only audit authorization, legal retention, exactly-once remote delivery, secure note redaction or staff identity. These require separately reviewed code/permissions and a controlled migration rollout. The case table permits neutral human review status only; the source current-source acceptance gate #114 is still open, and CASE-MOV-001 remains BLOCKED with zero safe speed pairs.

The disposable-PostgreSQL integration test verifies idempotent migration, exact installation/server/guild binding, foreign evidence rejection, duplicate action/fingerprint/delivery rejection and impossible sent/leased rows. Passing CI is **not** permission to merge: this migration would execute on live startup and must receive a distinct owner production-write approval under issue #124.
